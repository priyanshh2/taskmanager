# Deployment Guide: Vercel & Render

This guide provides step-by-step instructions for deploying **TaskFlow** into production:
- **Backend (Express API + MongoDB)**: Deployed on **[Render](https://render.com/)**
- **Frontend (React + Vite + Tailwind CSS)**: Deployed on **[Vercel](https://vercel.com/)**
- **Database**: Cloud-hosted **[MongoDB Atlas](https://www.mongodb.com/cloud/atlas)** (Free M0 cluster)

---

## Architecture Overview

```text
  ┌─────────────────────────┐          HTTPS / CORS          ┌─────────────────────────┐
  │         Vercel          │ ─────────────────────────────> │         Render          │
  │     (React Frontend)    │                                │     (Express Backend)   │
  │ https://your-app.vercel │ <───────────────────────────── │ https://api.onrender.com│
  └─────────────────────────┘                                └────────────┬────────────┘
                                                                          │
                                                                   Mongoose / TLS
                                                                          │
                                                                          ▼
                                                             ┌─────────────────────────┐
                                                             │      MongoDB Atlas      │
                                                             │     (Cloud Database)    │
                                                             └─────────────────────────┘
```

## Step 1: Set Up MongoDB Atlas (Database)

If you don't already have a MongoDB Atlas cloud database:

1. Sign up for free at [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas).
2. Create a free **M0 Sandbox** cluster.
3. Under **Security > Database Access**:
   - Create a database user (e.g. `taskflow_admin`) with password.
4. Under **Security > Network Access**:
   - Click **Add IP Address** -> select **Allow Access from Anywhere** (`0.0.0.0/0`) so Render services can connect.
5. Under **Database > Deployment > Database**, click **Connect**:
   - Choose **Drivers** (Node.js).
   - Copy your connection string. It looks like:
     ```text
     mongodb+srv://<username>:<password>@cluster0.abcde.mongodb.net/taskflow?retryWrites=true&w=majority
     ```
   - Replace `<username>` and `<password>` with your database user credentials.

## Step 2: Deploy Backend to Render

### Option A: Using the Render Blueprint (`render.yaml`) — Recommended

The repository includes a ready-to-use [`render.yaml`](render.yaml) file.

1. Log in to [dashboard.render.com](https://dashboard.render.com/).
2. Click **New +** -> **Blueprint**.
3. Connect your GitHub repository: `https://github.com/priyanshh2/taskmanager.git`.
4. Render will detect `render.yaml` and configure the `taskflow-server` web service.
5. Fill in the prompted environment variables:
   - `MONGODB_URI`: Your MongoDB Atlas connection string from Step 1.
   - `CLIENT_ORIGIN`: Your Vercel frontend URL (or leave blank initially; you will update it in Step 4).
   - `JWT_SECRET`: Automatically generated by Render, or supply your own 32+ character string.
6. Click **Apply**.
7. Once deployed, copy your backend URL (e.g., `https://taskflow-server-xxxx.onrender.com`).
   - You can test it by visiting: `https://taskflow-server-xxxx.onrender.com/api/health`.

---

### Option B: Manual Web Service on Render

If you prefer configuring the Web Service manually:

1. In Render Dashboard, click **New +** -> **Web Service**.
2. Select your repository: `priyanshh2/taskmanager`.
3. Configure the following settings:
   - **Name**: `taskflow-server` (or your preferred name)
   - **Language / Runtime**: `Node`
   - **Root Directory**: `server`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
4. Expand **Advanced** and set **Health Check Path** to:
   ```text
   /api/health
   ```
5. Add the following **Environment Variables**:
   | Variable | Value / Description |
   | :--- | :--- |
   | `NODE_ENV` | `production` |
   | `MONGODB_URI` | `mongodb+srv://<user>:<password>@cluster.mongodb.net/taskflow?retryWrites=true&w=majority` |
   | `JWT_SECRET` | Strong random 32+ character string (e.g., `openssl rand -hex 32`) |
   | `JWT_EXPIRES_IN` | `7d` |
   | `CLIENT_ORIGIN` | Your Vercel frontend URL (set in Step 4) |
6. Click **Create Web Service**. Wait for the build and deployment to succeed.

## Step 3: Deploy Frontend to Vercel

### Option A: Via Vercel Dashboard

1. Log in to [vercel.com](https://vercel.com/).
2. Click **Add New...** -> **Project**.
3. Import your GitHub repository: `https://github.com/priyanshh2/taskmanager.git`.
4. In the **Configure Project** screen:
   - **Root Directory**: Click **Edit** and select `client` (or leave as `./` — root [`vercel.json`](vercel.json) handles both!).
   - **Framework Preset**: `Vite`
   - **Build Command**: `npm run build` (or default)
   - **Output Directory**: `dist` (or default)
5. Expand **Environment Variables** and add:
   | Key | Value |
   | :--- | :--- |
   | `VITE_API_URL` | Your Render backend URL from Step 2 (e.g., `https://taskflow-server-xxxx.onrender.com`) |
6. Click **Deploy**.
7. Once completed, Vercel will assign a production URL (e.g., `https://taskmanager-xxxx.vercel.app`).

---

## Step 4: Link Frontend & Backend (Final CORS Step)

1. Return to your Render Dashboard for `taskflow-server`.
2. Go to **Environment** tab.
3. Set or update the `CLIENT_ORIGIN` variable to your Vercel URL:
   ```text
   CLIENT_ORIGIN=https://taskmanager-xxxx.vercel.app
   ```
   *(Multiple origins can be comma-separated, e.g.: `http://localhost:5173,https://taskmanager-xxxx.vercel.app`)*
4. Click **Save Changes**. Render will automatically trigger a zero-downtime redeploy.

## Verification Checklist

Once deployed:

- [ ] **Backend Health**: Visit `https://your-render-url.onrender.com/api/health` — should return `200 OK` with `"database": "connected"`.
- [ ] **Frontend Loading**: Visit `https://your-vercel-url.vercel.app` — should render the TaskFlow welcome/login screen.
- [ ] **User Registration**: Register a new user account on the live site.
- [ ] **Task CRUD**: Create, update, toggle complete, and delete tasks.
- [ ] **SPA Refresh**: Refresh the browser on any view — Vercel rewrites in `vercel.json` ensure you don't receive a 404.
- [ ] **Dashboard Stats**: Verify live statistics update properly in production.

## Key Configuration Files Reference
